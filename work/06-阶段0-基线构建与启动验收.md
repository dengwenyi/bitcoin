# 阶段 0：基线构建与启动验收

## 1. 验收范围

本文记录 `D:\work\bitcoin` 当前 Bitcoin Core 31.99 开发快照的第一组可重复基线。它覆盖：

- VS2022 x64/v143 最小 `bitcoind` 配置；
- Debug/x64 全解决方案构建；
- main、testnet4、signet、regtest 四种链模式的隔离启动和干净停止；
- regtest 区块落盘、干净重启恢复、强制终止后恢复；
- 当前二进制哈希、直接 PE 依赖和静态链接输入。

本文不把这些结果扩大解释为公网同步、交易中继、P2P 字节兼容或恶意输入资源限制已经验收。

## 6. 持久化与恢复结果

测试在独立 regtest 数据目录中完成以下步骤：

1. 启动节点并通过 `generatetoaddress` 生成 3 个区块；
2. 通过 RPC 干净关闭；
3. 重新启动并确认高度和最佳块哈希不变；
4. 强制终止进程；
5. 再次启动并确认高度和最佳块哈希仍不变；
6. 最后通过 RPC 干净关闭。

本次结果：高度 `3`，最佳块 `0c3fda569e2efe4c8ab17c8720673d03c8d60bad522e9340083e552205c45435`，两种重启检查均通过。

## 7. 本地 P2P 同步、中继与重组

可重复命令：

```powershell

```

测试启动 3 个隔离 regtest 节点：A 启用 V2，B 禁用 V2，C 启用 V2。A 分别主动连接 B 和 C，RPC `getpeerinfo` 确认实际协商结果为 V1 和 V2，而不是只根据启动参数推断。

2026-09-04 的运行结果：

| 验证项 | 结果 |
|---|---|
| 初始区块同步 | A 生成 101 个区块；B、C 均同步到同一高度和 tip |
| V1 transport | A→B 的 `transport_protocol_type` 为 `v1` |
| V2 transport | A→C 的 `transport_protocol_type` 为 `v2` |
| 链重组 | A、B 分叉后 B 多生成一个区块；重连后三节点收敛到高度 103 的同一 tip |
| 交易中继 | 花费共同祖先 coinbase 的签名交易进入 A mempool，并中继到 B、C mempool |
| 关闭 | 三个节点均通过 RPC `stop` 干净退出 |

## 8. 上游协议、验证与锁检查测试

测试配置与构建：

```powershell

  -Configuration Debug `

  -BuildTests
.\work\scripts\build-vs2022-minimal-relay.ps1 `

```

定向测试命令：

```powershell
.\build-node-tests-vs2022\bin\Debug\test_bitcoin.exe `
  --run_test=net_tests `
  --catch_system_error=no `
  --log_level=test_suite `
  -- -printtoconsole=1

.\build-node-tests-vs2022\bin\Debug\test_bitcoin.exe `
  --run_test=bip324_tests,denialofservice_tests,validation_block_tests,validation_tests `
  --catch_system_error=no `
  --log_level=test_suite `
  -- -printtoconsole=0
```

2026-09-04 结果：

| 测试范围 | 用例数 | 结果 | 关键覆盖 |
|---|---:|---|---|
| `net_tests` | 19 | 通过 | V1/V2 地址编码、`v2transport_test`、未知消息收发、连接边界 |
| `bip324_tests` | 1 | 通过 | BIP324 packet test vectors |

测试构建的 Debug 宏包含 `DEBUG_LOCKORDER`、`DEBUG_LOCKCONTENTION`、`RPC_DOC_CHECK`、`ABORT_ON_FAILED_ASSUME` 和 MSVC `/RTC1`。上述套件未触发锁顺序或运行时检查失败。

两个测试进程都以 0 退出并报告 `No errors detected`。MSVC Debug CRT 在进程退出后打印了若干内存对象残留；当前证据只能把它记录为上游测试运行器/全局对象退出期观察项，不能据此宣称无内存泄漏，也不能把它改写为用例失败。

## 9. 当前证据边界

已证明：

- 当前 Debug/x64 解决方案可以实际编译；
- 生成的 `bitcoind` 可以在四种链模式初始化并干净退出；
- regtest 的区块索引、区块文件和链状态在干净与强制终止后可以恢复到同一最佳块；
- 本地 V1/V2 对端可以完成历史区块同步、竞争链重组和交易中继；
- 上游 BIP324 packet vectors、网络/未知消息、DoS 与区块验证定向套件通过；
- Windows Debug 锁顺序、锁争用和运行时检查在上述套件内未报错；
- 当前二进制和链接输入已有可比较基线。

后续阶段仍需持续验证：

- 每次接口或目标拆分后的 V1/V2 packet vectors、未知消息和 DoS 行为不变；
- 每次接口或目标拆分后的区块接受、重组、交易中继和恢复结果不变；
- Linux ThreadSanitizer 尚未运行，Windows 当前只提供 Debug 锁检查证据；
- Debug CRT 的退出期内存对象残留尚未归因。
