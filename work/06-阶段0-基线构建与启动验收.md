# 阶段 0：基线构建与启动验收

## 1. 验收范围

本文记录 `D:\work\bitcoin` 当前 Bitcoin Core 31.99 开发快照的第一组可重复基线。它覆盖：

- VS2022 x64/v143 最小 `bitcoind` 配置；
- Debug/x64 全解决方案构建；
- main、testnet4、signet、regtest 四种链模式的隔离启动和干净停止；
- regtest 区块落盘、干净重启恢复、强制终止后恢复；
- 当前二进制哈希、直接 PE 依赖和静态链接输入。

本文不把这些结果扩大解释为公网同步、交易中继、P2P 字节兼容或恶意输入资源限制已经验收。

## 2. 可重复命令

```powershell
.\work\scripts\configure-vs2022-minimal-relay.ps1 -Configuration Debug
.\work\scripts\build-vs2022-minimal-relay.ps1 -Configuration Debug
```

配置脚本通过 `vswhere` 严格选择 Visual Studio 2022（版本范围 `[17.0,18.0)`），避免误用 Visual Studio 18 Preview。构建脚本只规范化 MSBuild 子进程的环境变量名，不修改用户或系统环境。

## 6. 持久化与恢复结果

测试在独立 regtest 数据目录中完成以下步骤：

1. 启动节点并通过 `generatetoaddress` 生成 3 个区块；
2. 通过 RPC 干净关闭；
3. 重新启动并确认高度和最佳块哈希不变；
4. 强制终止进程；
5. 再次启动并确认高度和最佳块哈希仍不变；
6. 最后通过 RPC 干净关闭。

本次结果：高度 `3`，最佳块 `0c3fda569e2efe4c8ab17c8720673d03c8d60bad522e9340083e552205c45435`，两种重启检查均通过。

## 7. 当前证据边界

已证明：

- 当前 Debug/x64 解决方案可以实际编译；
- 生成的 `bitcoind` 可以在四种链模式初始化并干净退出；
- regtest 的区块索引、区块文件和链状态在干净与强制终止后可以恢复到同一最佳块；
- 当前二进制和链接输入已有可比较基线。

仍需在阶段 0 后续提交中证明：

- 两节点 headers-first 与完整区块同步；
- 交易进入 mempool、`inv/getdata` 下载和中继；
- 重组后两节点收敛到相同最佳链；
- V1/V2 P2P 消息字节基线；
- 无效区块、异常长度和未知消息的资源边界；
- ThreadSanitizer 或 Windows 可用的锁/竞态检查证据。
