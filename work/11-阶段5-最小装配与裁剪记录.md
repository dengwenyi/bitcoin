# 阶段 5：最小装配与裁剪记录

本文记录 `D:\work\bitcoin` 当前 Bitcoin Core 31.99 开发快照替换进程装配入口的增量实施。每个切片必须先完成配置、实际编译、定向测试和运行对照，再提交和推送。

## 1. 建立过渡 `bitcoind_min` composition root

### 1.1 改动

- 新增默认关闭的 CMake 选项 `BUILD_MINIMAL_DAEMON`；
- 新增独立可执行目标 `bitcoind_min`；
- VS2022 最小标准中继配置脚本显式启用该目标；
- 原 `bitcoind` 目标保持不变，继续作为兼容行为基线。

本切片有意让 `bitcoind_min` 与 `bitcoind` 使用相同入口源文件并链接同一个 `bitcoin_node`。因此它仍然链接 `btc_node_optional`，仍包含 RPC、REST、index、miner 等上层对象。本切片只建立可并行比较的装配入口，不代表已经完成物理裁剪。

### 1.2 配置与编译证据

以下三套 VS2022 Debug/x64 配置重新生成成功，配置摘要均显示 `bitcoind_min=ON`：

- `build-node-relay-vs2022`；
- `build-node-tests-vs2022`，启用 `BUILD_TESTS`；
- `build-node-fuzz-vs2022`，启用 `BUILD_FOR_FUZZING`。

实际编译和链接结果：

- `bitcoind.exe`：成功；
- `bitcoind_min.exe`：成功；
- `test_bitcoin.exe`：成功；
- `fuzz.exe`：成功。

构建日志明确包含 `btc_node_optional.vcxproj`，这是本切片仍未裁掉上层服务的直接链接证据。

### 1.3 运行差分

`bitcoind` 与 `bitcoind_min` 分别在独立数据目录运行阶段 0 基线脚本，结果均为：

- main、testnet4、signet、regtest 四种链模式启动、RPC 就绪并干净退出；
- 四种链模式报告的 genesis、初始高度、IBD 状态、网络版本和 mempool 加载状态一致；
- regtest 生成 3 块后，干净重启与强制终止后的恢复均回到相同 best block。

两者二进制因目标名称、资源和链接产物不同而具有不同文件大小与 SHA256；行为比较不要求二进制字节相同。

另以 `bitcoind_min` 运行三节点本地网络测试：

- V1 和 V2 transport 分别协商成功；
- 101 块初始同步后三个节点 tip 一致；
- 竞争链重组后三个节点收敛到高度 103 的相同 tip；
- 同一交易进入 V1、V2 两个对端的 mempool。

### 1.4 定向测试

- 网络、BIP324、DoS、peer connection 和 peerman 共 27 项通过；
- validation block、validation、mempool 和 transaction validation 共 16 项通过；
- `p2p_transport_serialization`、`p2p_handshake`、`process_message`、`process_messages` 四个 fuzz harness 以 EOF 空输入运行通过；
- 所有最终进程退出码均为 0；单元测试输出 `No errors detected`。

Windows Debug CRT 退出期仍打印与阶段 0 基线一致的对象残留报告；由于测试进程退出码为 0，本文将其保留为既有观察项，不把它改写为本切片的新失败或无泄漏证明。

首次 fuzz 调用错误地把 harness 名作为位置参数，驱动在运行目标前提示必须设置 `FUZZ` 环境变量并退出 1。改用 `FUZZ=<target>` 后四个目标全部退出 0；前一次命令错误不计作 fuzz 用例结果。
