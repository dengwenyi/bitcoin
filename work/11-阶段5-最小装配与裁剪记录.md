## 2. 提取节点控制构建边界

### 2.1 改动

新增 `btc_node_control` 对象目标，接管原来直接编入 `bitcoin_node` 的下列控制职责：

- `init.cpp` 中的参数交互、层对象创建和进程生命周期协调；
- chainstate、mempool、数据库等装配参数与持久化辅助；
- `NodeContext`、UI 接口、警告、abort 和 noui 控制实现；
- 交易验证 facade 和 policy settings。

`bitcoin_node` 保留 wallet/dummy-wallet 组合适配，并显式链接 `btc_node_control` 与既有五个分层对象目标。嵌入 ASMap 的编译定义同步转移到真正编译 `init.cpp` 的 `btc_node_control`。本切片只改变对象归属和链接边界，不改变任何运行分支。

- `bitcoind.exe`、`bitcoind_min.exe`、`test_bitcoin.exe` 和 `fuzz.exe` 均重新链接成功；

### 2.3 证据边界

该切片证明控制源文件可以通过独立构建目标被兼容装配，但 `btc_node_control` 中的 `init.cpp` 仍直接调用 RPC、index、miner 和 fee estimator 实现，`bitcoin_node` 也仍链接 `btc_node_optional`。下一步需要为最小装配建立明确的服务能力选择，不能仅从链接清单删除对象目标后依赖偶然的未引用符号。

## 3. 建立不含上层可选服务的最小链接图

### 3.1 最小装配选择

新增以下仅供 `bitcoind_min` 使用的目标：

- `btc_node_control_min`：以 `BITCOIN_MINIMAL_NODE` 编译生命周期控制路径，并排除 `node/interfaces.cpp`；
- `btc_peer_protocol_min`：保留区块/交易/地址中继，拒绝未提供索引的 compact-filter 服务；
- `btc_tx_relay_min`：保留 mempool、RBF、package、orphan、reconciliation 和交易下载路径，跳过 txindex 查询；
- `bitcoin_node_min`：只装配 chainstate、transport、最小 control、最小 peer protocol 和最小 tx relay。

`bitcoind_min` 改为只链接 `bitcoin_node_min`。CMake 配置期断言禁止它直接链接兼容 `bitcoin_node`、`btc_node_optional` 或三个完整上层目标。生成的 `bitcoind_min.vcxproj` 与 `bitcoin_node_min.vcxproj` 中 `btc_node_optional` 引用数为 0。

完整 `bitcoind` 仍链接 `bitcoin_node` 和 `btc_node_optional`，作为 RPC/index/miner 行为兼容目标。

### 3.2 能力边界

最小装配明确关闭：

- HTTP、JSON-RPC 和 REST 服务；
- txindex、txospenderindex、coinstatsindex 和 blockfilterindex；
- compact-filter 对外服务；
- fee estimator 的加载、周期 flush 和停机 flush；
- mining、完整 Node/Chain RPC 适配接口和 wallet 装配。

若显式请求 `-server=1`、`-txindex=1`、`-blockfilterindex=1` 或 `-coinstatsindex=1`，最小 daemon 在打开网络和数据库前返回清晰错误，不静默忽略配置。默认启动不创建 RPC cookie。

标准中继仍需要 `FeeFilterRounder` 对 feefilter 消息做隐私量化。该实现已从 `block_policy_estimator.cpp` 移到 `policy/fees/fee_filter.cpp`，归属交易中继目标；这保留中继协议行为，但不把完整 fee estimator 重新带回最小链接图。

`NodeContext` 中两个上层服务句柄改为 `shared_ptr`，让未启用这些服务的最小控制对象在析构时不产生对其具体析构实现的静态链接依赖；完整装配仍是唯一所有者，运行语义不变。

### 3.4 最终运行与测试

无 RPC 的 `bitcoind_min` 使用新增 `test-stage5-minimal.py` 验证：

### 3.5 失败驱动修正

- 初次无可选服务链接产生 77 个未解析符号，据此定位并逐项切断 HTTP/RPC、index、miner、fee estimator 与完整 interfaces 的真实依赖；修正后重新链接成功；
- 首次无 RPC smoke 因 bitcoind 默认把 `-server` 软设为 true 而被能力检查拒绝；最小入口改为默认 `-server=0` 后启动通过；
- 首次网络拓扑同时连接有链和空链节点，headers-sync peer 选择了空链端；调整为先从 source 完成同步、再由 sink 接入后，中继测试通过；
- 首次 V2 回归显示实际协商为 V1；日志与静态检查定位到 `NODE_P2P_V2` 能力声明误落入完整索引分支，移回共享 transport 路径后 V2 重组通过；
- 一次 vcpkg 临时 registry 初始化被受限环境拒绝创建 Git stdin，非受限原命令重跑成功，未将其计作源码构建失败。

### 3.6 阶段结论

阶段 5 的三项要求均已完成：已建立独立最小 composition root；最小目标不再链接 RPC、REST、index、wallet、miner 和 fee estimator 实现；不存在只被最小目标遗留引用、可以安全物理删除的上层源文件，因为兼容 `bitcoind` 仍明确引用它们。因此本阶段不删除仓库源文件，以保留并行行为基线。

剩余限制：Linux/TSAN、长时间公网 IBD、真实崩溃注入和跨版本数据目录迁移尚未运行，不能由本地 Windows Debug 回归替代。
