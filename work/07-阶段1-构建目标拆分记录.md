# 阶段 1：构建目标拆分记录

## 1. 当前切片

阶段 1 的第一刀新增 `btc_node_optional` 对象目标，将下列上层服务源码从 `bitcoin_node` 的直接源列表移出：

- HTTP RPC 与 HTTP server；
- REST；
- block filter、coin stats、transaction、txout spender indexes；
- miner、mining args、mini miner；
- PSBT node helper；
- fee estimator；
- blockchain、fees、mempool、mining、net、node、raw transaction 等 RPC handlers。

`bitcoin_node` 仍显式依赖并链接 `btc_node_optional` 的对象，因此这一刀只建立真实的编译目标边界，不改变 `bitcoind` 的可见行为，也不宣称二进制已经删除这些功能。

阶段 1 的第二刀新增 `btc_net_transport` 对象目标，将以下连接和传输实现从 `bitcoin_node` 的直接源列表移出：

- `bip324.cpp`；
- `net.cpp`；
- `i2p.cpp`、`torcontrol.cpp` 与 `mapport.cpp`。

这是过渡边界：当前 `net.cpp` 仍同时承载 `CConnman`、`V1Transport` 和 `V2Transport` 等实现，尚未形成最终的窄接口。`bitcoin_node` 继续显式依赖并链接该对象目标，以保持现有装配和运行行为。

阶段 1 的第三刀新增 `btc_tx_relay` 对象目标，集中承载交易池、交易图、下载与孤儿交易管理、交易 reconciliation、包策略、RBF/TRUC/ephemeral 策略和 private broadcast 实现。验证层和 `net_processing` 当前仍直接使用这些具体类型，因此这一刀同样只建立可编译、可检查的过渡边界，不改变策略或共识语义。

## 2. 依赖与生成器约束

Visual Studio 生成器第一次构建时，`bitcoin_node` 曾在 `btc_node_optional` 的对象生成前尝试归档 `httprpc.obj`，报 `LNK1181`。最终 CMake 同时保留：

- `target_link_libraries(bitcoin_node PRIVATE btc_node_optional)`：把对象纳入兼容目标；
- `add_dependencies(bitcoin_node btc_node_optional)`：显式固定 Visual Studio 构建顺序。

修正后生成顺序为：

```text
btc_node_optional.vcxproj
  -> bitcoin_node.vcxproj
  -> bitcoind.vcxproj
```

通过 `lib.exe /list bitcoin_node.lib` 已确认：

- `btc_node_optional` 的 HTTP、index、miner、PSBT、fee estimator、REST 和 RPC handler 对象仍存在于兼容库中；
- `btc_net_transport` 的 `bip324.obj`、`net.obj`、`i2p.obj`、`mapport.obj` 与 `torcontrol.obj` 也已纳入兼容库。
- `btc_tx_relay` 的 12 个交易中继与策略对象均已纳入兼容库。

这是预期结果，也是后续 composition root 替换前的行为保持机制。
