# 最小标准中继全节点裁剪实施步骤清单

## 1. 文档目的

本文档将《C++ 全节点 TCP/IP 式分层裁剪方案》转换为可执行的实施清单，目标是从现有 Bitcoin Core C++ `bitcoind` 出发，逐步得到一个保留标准交易中继能力的最小全节点。

本文档描述的是渐进式重构和裁剪，不是另写一个全新的节点实现。

## 2. 目标定义

最终目标必须保留：

- 完整区块头和区块同步；
- PoW、Script、交易、UTXO 和链重组验证；
- block/undo/chainstate 持久化和崩溃恢复；
- P2P 入站与出站连接；
- V1 和 BIP324 V2 transport；
- Peer 握手、反滥用和资源限制；
- mempool；
- 交易验证、孤儿交易、package/RBF/TRUC 策略；
- tx `inv/getdata`、交易中继和费用过滤；
- 必要的日志、配置、数据目录锁和安全关闭。

最终目标可以关闭：

- Qt GUI；
- 钱包；
- `bitcoin-cli`、`bitcoin-tx`、`bitcoin-util` 等独立工具；
- ZMQ、IPC、外部签名器；
- GUI/钱包/测试/benchmark/fuzz 专用目标；
- 非必要索引、REST 和挖矿扩展。

## 5. 允许的依赖方向

```text
bitcoind_min
  └─ btc_node_control
       ├─ btc_blocksync ──→ btc_p2p_protocol ──→ btc_net_transport
       │        │
       │        └────────→ btc_chainstate ──→ btc_consensus
       └──────────────────────────────────────→ btc_base

btc_txrelay 由 blocksync 或 relay facade 选择性注入。
```

禁止以下反向依赖：

- `btc_consensus → net`；
- `btc_chainstate → btc_blocksync`；
- `btc_net_transport → validation`；
- 共识层依赖 mempool relay policy；
- 下层依赖完整 `NodeContext`。

## 7. 风险与回退策略

### 高风险区域

- `validation.cpp`、`ChainstateManager` 和 UTXO 状态转换；
- `net_processing.cpp` 的 Peer、同步和交易路径；
- BIP324 V2 transport 状态机；
- shutdown flush、锁顺序和崩溃恢复；
- mempool/package/RBF 策略；
- P2P 资源限制和恶意 Peer 处理。

### 回退规则

- 每个阶段使用独立小提交；
- 保留原 `bitcoind` 目标作为行为参照；
- 新目标出现差分时优先回退适配层，不修改共识规则；
- 不使用目录级删除作为回退手段；
- 未通过验收前不删除旧实现。

## 8. 证据记录格式

每次实施记录以下四类证据：

1. 静态推断：源码、CMake 和依赖关系说明；
2. 编译证据：生成器、编译器、配置、目标和完整错误输出；
3. 运行证据：启动参数、日志、RPC/P2P 行为和退出结果；
4. 验收证据：区块、重组、交易中继、字节兼容、恢复和资源限制结果。

“配置成功”不能写成“编译成功”；“编译成功”不能写成“运行或网络同步验收成功”。
